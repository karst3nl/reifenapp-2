# Arbeitsregeln

- Ausschließlich dieses neue Repository bearbeiten; das alte Reifensuch-App-Repository nicht verwenden oder verändern.
- Originaldesign ohne ausdrückliche Anweisung nicht ändern.
- Bestehenden Code zuerst lesen und verstehen; keine unbegründeten Komplettumbauten.
- Kleine, nachvollziehbare Schritte und Commits; idiomatisches Go.
- Angemessene automatisierte Tests ausführen und Ergebnisse sowie ausgelassene Tests nennen.
- Keine unnötigen Module oder Frameworks.
- Niemals echte Kundendaten, Zugangsdaten, SQLite-Dateien oder Backups veröffentlichen.
- Bestehende lokale Datenbanken nicht ungefragt löschen, neu anlegen oder mit Testdaten überschreiben. Vor Migration bestehender Datenbanken Sicherheitsprüfung und Backup durchführen.
- Architekturentscheidungen und Startanleitung kurz dokumentieren.
- Projektübersicht: docs/projektuebersicht.md. Sie beschreibt auch spätere Meilensteine; nicht alles vorweg implementieren.
